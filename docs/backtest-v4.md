# §51 检验（v4）：预告池修好之后的重跑

> 结论先行：**v1–v3 的结论作废**。原因不是模型变了，是数据池子之前只有全量的 7%。
> 修好之后重跑，「八期全部不劣于随机基线」变成「4/8」；而且事件研究里那个
> 「随机基线」本身选错了——它是一篮子**被披露出来的坏消息**。
> 再补一个真正的全市场基线之后，业绩预告这个机械信号**没有显示出对全市场的稳定优势**。

## 零、v1–v3 为什么必须作废

东财业绩预告接口 `RPT_PUBLIC_OP_NEWPREDICT` **忽略 pageIndex**（第 1、2、3 页返回
完全相同的行），`pageSize` 也封顶 500。返回体里的 `count` 才是真实总量：2026-06-30
报告期真实 **4928 行**，而一页只有 500 行。

早先的取数每期只取第一页，于是：

| 报告期 | 旧池（公司数） | 新池（全市场／主板） |
|---|---|---|
| 2024-03-31 | 93 | 220／115 |
| 2024-06-30 | 165 | 1748／1430 |
| 2024-09-30 | 120 | 216／131 |
| 2024-12-31 | 116 | 2873／1564 |
| 2025-06-30 | 149 | 1663／1442 |
| 2025-12-31 | 91 | 3075／1625 |
| 2026-03-31 | 99 | 219／110 |
| 2026-06-30 | 115 | 1914／1593 |

**发现层的候选池和回测的事件组、对照组，全都建在这个 7% 的样本上。**

而且这个 7% 不是随机的：接口按 `NOTICE_DATE` 升序返回，取第一页 = **只拿到最早
披露预告的那批公司**。早期披露的往往是变动幅度最大的那批，所以旧池在两个方向上
都偏了——样本偏小，且偏极端。

修法是**用切分代替翻页**（`research/forecast_pool.py`）：按数值字段（变动幅度、
预告金额）递归二分，一遍按幅度、一遍按金额，取并集。9 个报告期覆盖率 97.5%–100%。

## 一、顺带修掉的两处取价缺陷

重跑时暴露出来的，不修的话新结论同样不可信：

1. **腾讯 WAF 限流返回 501**（请求量大时），旧代码把它当成「没有行情」返回空列表。
   空价格会让「无收益」混进中位数——那不是结论，是数据缺失，而回测照跑不误。
   现在 501 会被识别并切到同花顺兜底源（前复权，字段序与腾讯一致），失败的代码
   记进 `PRICE_MISSES`，报告里打出**行情覆盖率**。沪深300 基准同样加了兜底
   （同花顺 `hs_399300`），否则基准一缺，超额指标整列都是空的。
2. **行情缓存只按代码存**，同一只股票在不同报告期需要的区间不同，后一次会拿到
   前一次的窗口——数据看着有、日期却不对，持有期收益就算不出来。现在缓存存合并
   并集，窗口覆盖不了就重取。

修完之后，同一个报告期的事件研究从 **20 分钟降到 2.8 秒**（bootstrap 改用 numpy
向量化 + 行情加进程内缓存 + 覆盖判断放宽 7 天余量 + 结束日期夹到今天）。

## 二、对照组选错了：v4 最重要的方法论发现

事件研究里的对照组是「同报告期发了预告、但变动幅度不达标」的公司。

**这批公司本身就是坏消息集合**——小幅预减、首亏、续亏的居多（预告只对大幅变动
者强制披露，落在门槛以下的多半是变差或微增）。拿它当基线，测的是
「挑强的比挑不强的强多少」，**不是**「跟着预告买是否跑赢市场」。

而发现层面对的恰恰是市场：它从全市场里挑出预告的公司。所以基线必须是**同期随机
A 股**。

补上这个基线（`scripts/market_baseline.py`：申万成分股表的全市场 5221 只减去当期

## 五、结论

0. **v1–v3 的结论作废**：预告池之前只有全量的 7%，且偏向最早披露的一批。
   「八期全部不劣于随机基线」在修好的数据上是 **4/8**。
1. **「业绩预告大幅变动」这个机械信号，没有显示出对全市场的稳定优势**：
   八期十六格里中位更优 9 期、胜率更优 12 期——大致是硬币的两面。
   对着坏消息集合看（+1.73pct 中位超额）会高估它。
2. **门槛方向没变但幅度缩水**：30% 仍优于 50%、100%，极端幅度仍是噪音。
3. **仓位结构仍是硬约束**：20 只 × 5% 下强预告组合最差回撤 17.07%，
   贴着 20% 的账户预算；集中持股会让信号消失这一点没变。
4. **基准的选择比信号本身更值得警惕**：这一轮的教训不是「信号弱」，
   是「用坏消息集合当基线会把方向读反」。以后任何对照都要先问：
   这个对照组是被我挑出来的，还是自然形成的？
5. **发现层的定位要改**：它不是 alpha 来源，是**研究对象的提议器**。
   真正的价值在线索之外——卡片（资本轨迹、同业对照、行业共振、单季拆解、
   治理与风险）这些机械筛选给不了的东西。

## 六、下一步（按优先级）

1. **把检验对象换成卡片本身**：用已积累的卡片做「卡片状态（观察/降级）vs 后续
   20/60 日表现」，再对照同期同行业随机股票。卡片检验集随卡片积累自己长大，
   而且问的是我们真正在用的东西。v3 就列了这一条，现在的结论更支持做它。
2. **组合层补真市场基线**：现在的随机基线是池内随机，要加一条「随机 A 股」，
   才能把「信号优势」和「池子效应」分开。
3. **扩大报告期**（2023 及更早），并对每一期做 point-in-time 复核。
4. **组合层补涨跌停不可卖、停牌不可卖、T+1 的卖出限制**。
5. **把「账户规模」变成发现层的一等输入**：候选池应随账户规模变化。

## 七、局限

1. 对照组是「同报告期非强预告」——**不是**市场基线；市场基线见第二节与
   `scripts/market_baseline.py`
2. 池子按主板代码粗筛，未按市值区间过滤（前视偏差）
3. 退市与停牌样本缺失，幸存者偏差；申万成分股表是当前的清单
4. 费用按固定费率估算，滑点 0.2% 是假设值；未含冲击成本
5. 持有期固定，无择时；假设所有持仓都能按收盘价卖出
6. 每期独立起算，未含跨期资金与持仓的连续性
7. 市场基线每期抽 500 只随机股票，中位数本身有抽样噪声（未给区间）
8. 一季报与三季报报告期的预告是自愿披露，池子只有一百多家（年报/中报期一千多
   到三千家），两类的可比性不同
